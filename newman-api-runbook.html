Framework Architecture

flowlib Stack

All flows are generated by Python scripts that produce Postman v2.1 JSON collections. The framework lives in scripts/flowlib/:

ModuleRole
core.pyreq() builds steps with skip-on-fail, build_setup()/build_teardown(), global_capture_test() (5xx tracker), build_collection()/write_flow()
auth.pyCollection-level Keycloak pre-request: password grant to {{keycloak_token_url}}, auto-refresh within 60s of expiry
setup.pyShared reusable steps: create_ds_step(), fetch_entities_step(), create_schema_graph_step(), full_setup_steps(), cleanup_steps()

Skip-on-Fail Pattern

Every req() step checks _flow_failed in the pre-request script. If a critical step fails, it sets this variable and all subsequent steps (except teardown) redirect to a harmless health URL. Teardown always runs (skip_on_fail=False).

Global 5xx Tracker

A collection-level test runs after every request. Any 5xx response registers a hard failure assertion, except for soft-exempted endpoints: /synapse/namespace/status, /test-connection/sample-records, /s3-upload/*, Excel steps.

Regenerating Flows

cd postman-collections python scripts/gen_flow.py # all 29 flows python scripts/gen_flow.py realm tenant # specific flows python scripts/gen_flow.py --list # list available generators python scripts/gen_ds_flow.py # standalone DataSource-CRUD

Running Flows

Local (Newman CLI)

newman run flows/FLOW-DataSource-CRUD.postman_collection.json \ -e environments/minikube.postman_environment.json --insecure \ --env-var "test_username=admin" --env-var "test_password=admin123" \ --env-var "client_secret=hbrghdZl..." \ --env-var "driverType=POSTGRES" --env-var "dbHost=..." \ --timeout-request 60000

Batch Runner

python scripts/run_all_flows.py --user karthik --password karthik12 \ --env environments/minikube.postman_environment.json

Runs 17 flows in sequence with postgres + S3 + Keycloak credentials, prints pass/fail summary table.

How the Pipeline Runs Tests

All 4 services follow the same pattern in their jenkinsfile:

// 1. Clone postman-collections repo checkout([$class: 'GitSCM', branches: [[name: '*/main']], userRemoteConfigs: [[url: 'https://github.com/thequipu/postman-collections.git']]]) // 2. Copy flows + environments, sync secrets from S3 cp -r api-tests/repo/flows api-tests/flows aws s3 sync s3://quipu-api-tests/config/secrets/ api-tests/secrets/ aws s3 sync s3://quipu-api-tests/config/environments/ api-tests/environments/ // 3. Install Newman if needed which newman || npm install -g newman newman-reporter-htmlextra // 4. Load secrets from {env}.secrets.env → --env-var flags // 5. Run each selected flow: newman run "api-tests/flows/${flow}.postman_collection.json" \ -e "api-tests/environments/${testEnv}.postman_environment.json" \ ${insecureFlag} ${secretVars} \ -r cli,htmlextra,junit \ --reporter-junit-export "api-tests/reports/.../slug.xml" \ --reporter-htmlextra-export "api-tests/reports/.../slug.html" \ --timeout-request 60000 // 6. Publish: junit + archiveArtifacts + publishHTML // 7. Upload reports to S3 for historical tracking

Environment auto-selection: when DEPLOY_TO_MINIKUBE=true, the test env is overridden to minikube regardless of API_TEST_ENV. Onprem/local environments use --insecure for self-signed TLS.

Known Issues

Keycloak Token TTL (~3 minutes)

The eksquipu realm access token expires in approximately 3 minutes. For short flows this is fine, but for long flows like Realm-CRUD (61 steps), CTAS queries submitted to Trino can't be polled after the token expires. The PipelineTokenProvider enters an infinite 5-second refresh retry loop. This is a backend config issue, not a test issue.

Mitigation: Step 24 in Realm-CRUD uses soft-assert — it reports partial ingestion but doesn't fail the flow.

permanent=true blocked on eksquipu

Hard-delete (permanent=true) is blocked because memory_space migration V42–V44 has not been applied. The realm flow soft-deletes by default; pass --hard for migrated environments.

CSV DataSource requires raw AWS credentials

CSV datasources need real AWS accessKey/secret (raw, no aesRandomIV encryption) plus files[] with columnDetails. Excel datasources use server-side IAM. Pass S3 credentials via --env-var (not globals).

Excel/S3 5xx soft-exemptions

Steps that hit S3 upload endpoints or Excel staging may return 500 when S3 credentials are missing or files don't exist. These are soft-exempted in the global 5xx tracker so they don't cascade.
